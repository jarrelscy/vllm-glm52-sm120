# Exact cache-block cost of 8+8

The current TP4/DCP4 cache uses 3,502,592 bytes per rank for each 256 global tokens: `64 * (79 * 656 + 22 * 132)`. The 79 MLA caches include one MTP layer; the 22 indexer caches include 21 backbone indexers and one MTP indexer. MLA stores 512 FP8 NoPE bytes, 16 scale bytes, and 128 BF16 RoPE bytes per local token. Indexers store 128 FP8 bytes plus one four-byte scale. Uniform-type cache grouping sums these page sizes without padding the indexer pages to MLA size. The sparse backend requires physical block size 64, and DCP4 supplies 256 global tokens per block.

For the observed 4,196 blocks (1,074,176 tokens), allocated cache storage is 14,696,876,032 bytes per rank. The extra 8+8 payload plus codebooks is 1,983,360,000 bytes per rank: 566 whole cache blocks plus 892,928 bytes. With every other allocation unchanged, it displaces **566 or 567 blocks**, leaving **929,024–929,280 global tokens**. The one-block ambiguity is unavoidable because the logged 13.69 GiB available-memory budget omits its exact sub-block remainder. If that remainder is at least 892,928 bytes, 566 blocks are lost; otherwise 567 are lost.

This would not preserve the configured 1,048,576-token limit. Keeping that limit requires approximately another 1.63 billion bytes per rank beyond the existing cache headroom. This is a cache-layout calculation, not an 8+8 deployment or measurement of changed allocator/transient peaks. Native payload/codebook delta is supplied by the independent checkpoint audit; CUDA allocator rounding and changed temporary allocations are outside this estimate. LMCache's serialized tensor shape must not be used to infer native cache bytes.
